# SweetWave

Маркетплейс кондитерских изделий между Якутией и ДНР со сборными доставками — «волнами».
Чем полнее волна, тем дешевле доставка для каждого покупателя.

Проект сделан для IT-хакатона: функциональность базовая, код и структура — качественные.
Все логистические параметры вынесены в конфигурацию, ключевые бизнес-правила покрыты модульными тестами.

## Стек

- ASP.NET Core Razor Pages, C# (latest), `Nullable` включён, `TreatWarningsAsErrors`
- EF Core 8 + SQLite, миграции, автоматическое создание и заполнение базы при старте
- Cookie-аутентификация только для админки, корзина в `Session`
- Bootstrap 5, CsvHelper для импорта каталога, xUnit для тестов

## Запуск

```bash
git clone <репозиторий>
cd SweetWave

dotnet restore
dotnet run --project src/SweetWave.Web
```

Приложение откроется на `http://localhost:5194` (адрес из `Properties/launchSettings.json`).
При первом старте создаётся файл `src/SweetWave.Web/sweetwave.db`, применяются миграции и
загружается каталог из `src/SweetWave.Web/Infrastructure/Seeding/Data/catalog.csv` (20 позиций),
после чего создаются 12 волн — по 6 на каждое направление.

### Вход в админку

| Роль            | Логин   | Пароль      |
|-----------------|---------|-------------|
| Администратор   | `admin` | `change-me` |

Пароль и логин задаются в `src/SweetWave.Web/appsettings.json`, раздел `Admin`
(для продакшена лучше переопределить через переменные окружения `Admin__UserName` и `Admin__Password`).

### Проверка качества

```bash
dotnet build   # 0 предупреждений
dotnet test    # все тесты зелёные
```

## Как считается доставка

```
доставка = вес_кг × 500 ₽ × (1 − скидка/100) + 150 ₽ (если нужна термоупаковка)
```

| Заполнение волны | Скидка    |
|------------------|----------|
| ровно 50 % и ниже| нет      |
| более 50 %       | −20 %    |
| более 80 %       | −35 %    |

Пороги задаются массивом `Logistics:FillDiscounts`, поэтому новые скидки добавляются в конфигурацию
без изменения кода. Округление до целых рублей — `MidpointRounding.AwayFromZero`.

## Допущения

1. **Направление доставки определяется регионом производителя**: товары Якутии едут в ДНР, товары ДНР — в Якутию.
   В одной корзине разрешены товары только одной витрины, иначе показывается понятное сообщение.
2. **Стоимость заказа фиксируется в момент оформления**: цены, вес и скидка рассчитываются сервером из базы,
   данные клиента не используются. Позиции заказа хранят снимок данных (наименование, цена, вес).
3. **`temp_sensitive` означает шоколад и другие карамельно-шоколадные изделия**, которые нельзя отправлять
   без термоупаковки в холодные и жаркие месяцы (`Logistics:ThermoPackMandatoryMonths`).
4. **Приём заказов включительно по дату дедлайна**: волна открыта, пока сегодняшняя дата не больше `OrderCutoffDate`.
5. **Вместимость и минимальная загрузка волны фиксируются при её создании** из конфигурации
   (`MaxWaveLoadKg`, `MinWaveLoadKg`), поэтому изменение конфигурации не влияет на уже созданные волны.
6. **Заполнение волны считается по целым граммам**, деньги в SQL не суммируются (SQLite не умеет decimal),
   все денежные расчёты выполняются в памяти.
7. **Подарок**: получатель указывается в регионе доставки, текст открытки необязателен;
   для личного заказа получателем автоматически становится покупатель.
8. **Срок доставки** отображается как диапазон ориентировочных дат; в межсезонье (`Logistics:OffSeasonMonths`)
   к сроку добавляется `OffSeasonExtraDays`.
9. **Максимум 50 штук одного товара** в корзине — защита от случайного огромного заказа.
10. **Оплата демонстрационная**: кнопка «Оплатить (демо)» создаёт заказ, платёжных сущностей и интеграций нет.
11. **Страница подтверждения** показывает заказ только по номеру: покупатель не авторизуется,
    отслеживание требует номер заказа **и** телефон покупателя или получателя (телефоны сравниваются по цифрам).
12. **Поиск по каталогу** выполняется в памяти по уже отфильтрованной витрине, потому что SQLite
    сравнивает строки с кириллицей регистрозависимо.
13. **JavaScript** используется только для интерфейса (переключение блока получателя и подсказка про
    термоупаковку); весь расчёт выполняет сервер.
14. **Каталог** — условный CSV-файл на 20 позиций (10 Якутия / 10 ДНР). Организаторы могут заменить
    `Infrastructure/Seeding/Data/catalog.csv`, значения при импорте проверяются, неизвестные строки
    приводят к понятной ошибке.
15. **Сид выполняется, только если таблицы пусты**: существующие данные не перезаписываются.

## Сквозной сценарий проверки вручную

1. `/` → главная с двумя витринами и ближайшими волнами.
2. `/Catalog` → переключить витрину, выбрать категорию, найти товар, добавить в корзину.
3. `/Cart` → изменить количество, посмотреть вес и сумму.
4. `/Checkout` → заполнить данные (включить «Это подарок» и указать получателя с открыткой),
   выбрать волну: видно заполнение до/после, скидку, доставку, срок и итог.
5. «Оплатить (демо)» → `/Orders/Confirmation?number=SW-XXXXXX` с номером и зафиксированной стоимостью.
6. `/Orders/Track` → найти заказ по номеру и телефону, увидеть таймлайн статусов.
7. `/Admin/Login` → товары, волны, заказы.
8. В админке отправить волну (должна быть набрана минимальная загрузка) → заказы волны станут «в пути».
